# Разделение интерфейса Telegram Monitor

Это набор исходных файлов для существующего приложения Windmill, а не отдельный запускаемый проект.

## Установка

1. Сделайте копию текущей папки приложения.
2. Скопируйте содержимое этой папки в существующую папку приложения рядом с index.tsx, package.json и raw_app.yaml. Замените App.tsx и index.css; добавьте остальные файлы и каталоги. Не заменяйте целиком папку приложения.
3. Существующие backend/, wmill.ts (если он присутствует), index.tsx, package.json и raw_app.yaml не изменяйте. Windmill обеспечивает модуль wmill. В архиве намеренно нет его поддельной реализации.
4. Старый PostTable.tsx рядом с App.tsx больше не используется: таблица теперь находится в components/PostTable.tsx. После переноса старый файл можно удалить.
5. В корне telegram-parser выполните `npx wmill sync push`. Проверьте список перед подтверждением. Если предлагаются удаления backend-скриптов или ресурсов, не подтверждайте их: перенос не требует этих удалений.
6. Откройте приложение в Windmill, проверьте сборку и опубликуйте через Deploy, если требуется.

## Где что менять

| Файл | Назначение |
| --- | --- |
| App.tsx | Общая оболочка и выбор страницы |
| components/Sidebar.tsx | Список пунктов меню и кнопки перехода |
| components/PostTable.tsx | Общая таблица публикаций |
| pages/ProfilePage.tsx | Весь интерфейс профиля (пока заглушка) |
| pages/ControlsPage.tsx | Весь интерфейс контролей |
| pages/FavoritesPage.tsx | Весь интерфейс избранного |
| hooks/useMonitor.ts | Состояние, первичная загрузка, обработчики действий |
| api/monitor.ts | Именованные обёртки над вызовами Windmill |
| types.ts | Общие типы Post, Page, Action |
| index.css | Общие стили |
| styles.d.ts | Объявление типа для импортов CSS |

`useMonitor` — пользовательский React hook. App вызывает его один раз и передаёт результат страницам через свойство monitor. Поэтому переключение страниц не очищает черновик промпта, список публикаций или избранное и не вызывает повторную начальную загрузку.

Страницы вызывают обработчики из monitor. Обработчики вызывают функции api/monitor.ts, а те обращаются к Windmill. Прямых обращений backend.a … backend.g в страницах нет.

## Проверка после установки

- Открывается «Контроли», видны прежние поля и таблица.
- Переходы «Профиль», «Контроли», «Избранное» работают.
- Введённый, но не сохранённый промпт не сбрасывается при переключении разделов.
- Добавленный пост появляется в избранном. После удаления исчезает из избранного, но остаётся в контролях.
- При обновлении вкладки избранное очищается — это прежнее временное поведение.
- Сохранение промпта и тематик работает. Сбор, обработку и отправку проверяйте осознанно: они запускают реальные внешние действия, в том числе платные вызовы ИИ и отправку в Telegram.

## Что не менялось

- Нет новой авторизации, личных тарифов, ограничения каналов или изоляции пользователей.
- Избранное хранится только в памяти App, не в базе.
- Переходы используют состояние React; адрес страницы и история браузера не меняются.
- Канал, адрес Browser Worker, получатель Telegram и лимиты остались прежними и находятся в api/monitor.ts.
- Ширина интерфейса по-прежнему рассчитана на настольный экран.
- Для окончательной проверки нужен ваш реальный Windmill с его backend-модулем.

## Выполненные проверки

- TypeScript strict и сборка esbuild: пройдены с тестовым модулем Windmill.
- Тест взаимодействий React в jsdom: три раздела, добавление и удаление избранного, сохранение исходного поста, сохранение черновика при переходах и вызов сохранения промпта — пройдены.
- Тестовые ответы Windmill и тестовые зависимости не включены в архив. Реальные ИИ-вызовы и отправки Telegram при проверке не выполнялись.
- Визуальная проверка в реальном Windmill и проверка его сгенерированных типов ещё нужны.
